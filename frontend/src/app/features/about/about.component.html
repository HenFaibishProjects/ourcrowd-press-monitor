Project Overview

A concise technical summary for reviewers.

What this project does

OurCrowd Press Monitor tracks press mentions for a curated list of OurCrowd portfolio companies. A scheduled collection run queries a live news source, filters articles by relevance using a local language model, classifies sentiment, and persists results to a relational database. A read-only Angular dashboard exposes the aggregated data by quarter.

Backend Node.js · NestJS
Frontend Angular (standalone components)
Database PostgreSQL
LLM Ollama (local, gemma3:270m)
Live provider GDELT DOC API
Demo provider FileNewsProvider (deterministic)

Architecture

A simple linear collection pipeline inside a single NestJS application.

🏢 Company list JSON source of truth
→
🔍 NewsProvider GDELT or FileNewsProvider
→
🔗 URL normalisation Deduplication
→
📄 Enrichment Optional article context
→
🤖 Ollama Relevance + sentiment
→
🗄️ PostgreSQL Persistent store
→
⚡ REST API NestJS controllers
→
📊 Angular dashboard + Alert console output

Main decisions

Why NestJS

NestJS provides a structured, module-based layout that maps naturally to the feature areas of this project (companies, mentions, news, scheduling, alerts). Its built-in DI container keeps services composable without manual wiring. The overhead is justified because the project is large enough that unstructured Express would become harder to reason about.

Why PostgreSQL

PostgreSQL gives real foreign key enforcement, a UNIQUE(companyId, url) constraint as a race-condition guard, and a query planner that handles reasonable filtering without workarounds. SQLite was considered but ruled out because type-safe constraints and migration tooling are simpler with PostgreSQL at this scope.

Why Ollama

The assignment specifically required a locally hosted LLM. Ollama eliminates API keys, network latency to a cloud provider, and per-call cost. The task is narrow (relevance + sentiment) so a small, fast model (gemma3:270m) is defensible. A reviewer can reproduce the exact run on a standard development machine.

Why GDELT

GDELT DOC API is public, free, requires no API key, and covers global English-language news. It has rate limits and result caps, so the collection pipeline wraps it with retry logic and honors Retry-After. For a take-home, the tradeoff of occasional rate-limiting is acceptable given the zero-friction setup.

Why FileNewsProvider exists

GDELT is a live public endpoint that can be temporarily unavailable or rate-limited. FileNewsProvider lets a reviewer run the full collection pipeline deterministically using a committed, verified article fixture :without inserting fake rows directly or bypassing any real logic. The same CollectionService, Ollama classifier, and PostgreSQL layer are used in both paths.

Why a modular monolith

Splitting into microservices at this scope would add coordination overhead (service discovery, network contracts, distributed transactions) with no benefit. A modular monolith preserves all the seams needed for future extraction while remaining simple to run locally with a single npm run dev. It is also easier for a reviewer to trace end-to-end behavior.

If I were taking this further

The following were intentionally not included in this take-home. Each would be justified by a concrete scaling or reliability problem, not added upfront.

  • Queue / PubSub: decouple collection from API serving; enable dead-letter handling and retry visibility.
  • Worker-based processing: move Ollama calls and article enrichment out of the main process to avoid blocking.
  • Bounded concurrency: process multiple companies in parallel with a configurable concurrency limit, rather than strictly sequentially.
  • Distributed scheduling: use an external scheduler (e.g. Cloud Scheduler, pg-boss) so multiple replicas don't trigger duplicate runs.
  • Stronger observability: structured JSON logs, metrics (e.g. Prometheus), distributed tracing (e.g. OpenTelemetry).
  • Managed PostgreSQL: with connection pooling (PgBouncer), automated backups, and point-in-time recovery.
  • Better article extraction: a proper headless-browser fallback or a managed extraction service for paywalled or JS-rendered pages.
  • Labeled evaluation dataset: a human-labeled set of (article, company, expected-sentiment) triples to measure and iterate on model quality.

Reviewer quick start

Run these commands from the repository root. Docker must be running.

npm install
docker compose up -d
npm run db
npm run companies:setup
ollama pull gemma3:270m

# Deterministic demo run (FileNewsProvider):
npm run collect -- --companies=BioCatch --quarter=2026-Q3

# Start both servers in development mode:
npm run dev
